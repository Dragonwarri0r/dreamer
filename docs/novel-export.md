# 小说离线导出

在「内容与制作 → 章节书架 → 离线审阅」点击「导出小说」。默认生成一个 UTF-8 TXT；也可选择每 10 万字，或自定义每个文件的万字数。结果提供本地保存目录、复制目录按钮和逐文件下载链接。

- 范围为当前工程所有已保存的非空章节正文，含各写作状态，不受筛选、分页、书签和选中章节影响。仅有提纲的空章跳过并显示数量。
- 按章节序号排序（同序号以章节 ID 排序），包含书名、卷名和章名，原样保留正文，不导出梗概、备注或尚未采纳的提案。未保存的编辑会提示；导出不会自动保存编辑。
- 字数按 Unicode 字符计数，包含标点，不计空白和自动添加的标题。达到目标字数前在章节边界分文件；超出目标的单章保持完整并单独成文件。因此每个文件通常略少于所选字数。
- 每次导出保存到 `<DREAMER_DATA_ROOT>/exports/novels/<projectId>/<requestId>/`。`manifest.json` 保留章节 ID、版本和正文摘要供核对。不同导出互不覆盖；页面展示上次导出的时间，后续正文变化需再次导出。
- 导出是本地读取与文件写入，不调用写作 Agent 或媒体 Provider，不更改章节、检查点、任务和视频设置。

## 接口与恢复

`POST /api/novel-export`，JSON：`{projectId, requestId, maxCharacters}`。`maxCharacters` 默认为 `0`（全文）；正数为分文件字数目标。返回目录、计数及文件下载地址。沿用 Host 会话、Origin 和 CSRF 检查。

同一请求 ID 的重复提交返回原导出，即使期间正文已修改；更改分文件参数会返回冲突。页面持久保存未确认请求，断线或刷新后点「重试导出」恢复。输出通过临时目录写完后整体重命名，避免暴露半成品。

`GET /api/novel-export/file?projectId=…&id=…&part=0` 按已保存清单提供附件下载，需要本地会话，不接受任意文件路径。

## 定向检查

- `node --import tsx --test tests/novel-export.test.ts`：Unicode、排序、完整章节分文件、1001 章全量读取、来源不变、幂等重试、文件名和下载鉴权。
- `npm run build && node --import tsx scripts/browser-novel-export.ts`：隔离工程验证筛选下全量导出、下载、10 万字和自定义分文件、丢失响应后刷新重试、未保存提示、390px / 320px 排版。证据保存到独立的 `test-results/novel-export-*` 目录。
