# 长篇写作与短片编排

2026-10-20 用户追加需求：同一工程可能持续写作上千章；人工与 Agent 都要能快速找到内容；一条约两分钟的视频可取材两章并包含多个分镜。

## 交付范围与顺序

沿用已有开发 spec，不新增技术验证阶段。

| 改进 | 对应 spec / Roadmap | 本轮实现 |
|---|---|---|
| I07 千章定位与写作 | 02、04 / P2 | 章节身份、卷、序号、梗概、正文、进度；每页 30 章；章节号 / 标题 / 正文检索；卷与进度筛选；书签、最近阅读、前后章 |
| I08 人与 AI 共用范围 | 03、08 / P2–P3 | 摘要检索、固定引用、正文字符分页；章节 / 选区 / 制作单发给 Agent；局部正文提案、人工批准和基准冲突保护 |
| I09 章节到短片的编排 | 05、07 / P3 | 多章制作单、独立镜头顺序与时长、目标预算、缺画面提示、范围内分镜视图、只包含所选镜头的固定预演 |

## 使用方式

1. 在“内容与制作 → 章节书架”创建或查找章节。输入 `#1024`、`第1024章` 或正文关键词均可定位；卷和进度可组合筛选。书签是独立视图，阅读后自动记录最近章节。
2. 打开章节，写正文和梗概。长章只在打开时读取。正文选区可以发送给 Agent；保存、未保存草稿恢复、撤销、版本和独立窗口沿用原机制。
3. 在书架勾选两章，点“制作 2 分钟短片”。制作单自动收集这两章下现有场景关联的镜头；没有镜头时，可以“让 Agent 编排分镜”，也可以先在章节中添加改编场景。
4. 在制作单调整镜头先后顺序、每镜编排秒数和目标片长；移出章节会同步移出其镜头，可撤销；“收集章节新镜头”补入后续创建的分镜。“均分目标时长”给出一个可编辑的初始时间预算。原镜头自身时长及其他制作单不跟着变。
5. “分镜视图”只打开本片镜头。“预览草稿”保存制作单并打开可连续试听的 Cut；同版本优先继续原剪辑，保留配音与字幕。“更多 → 按当前镜头重建草稿”读取最新采用素材，另建 Cut。“生成本片预演”冻结当前剪辑为 Build，再由已有 FFmpeg 执行。动态素材不足时提示具体缺口，补足素材或主动调整时长后重建，制作预算不会自动缩短；缺图镜头显示占位，不能当作已完成视频。
6. 草稿播放器可跳镜、输入秒数、逐帧和开关声音 / 字幕；“修改当前镜头”回到关联对象。固定成片也可按镜头名称跳转并返回草稿剪辑。局部文字提案默认只展示修改及相邻上下文，随时可展开完整正文比较。

## 数据与边界

- `Chapter` 属于 Story：稳定 ID、全书序号、卷名、梗概、正文、写作进度。`Scene.chapterId` 表达当前改编归属；章节正文与场景剧本块保持独立。
- `Episode` 是短片制作单：`chapterIds`、有序 `shotIds`、`shotFrames` 和 `targetSeconds`。同一个 Shot 可参与不同制作单；“均分时长”只改当前制作单。
- Cut 固定 `episode` 和 `chapters` 引用以及原有 Shot / Take / Artifact。更改章节、排序或时长不会追写历史 Cut / Build。
- 旧工程没有章节仍可按原流程创作。超过 500 镜头的整工程预演要求先分成制作单，避免误把全书送去合成；这不是模型内存门禁。每单最多 100 章 / 500 镜头、最多 60 分钟。
- SQLite schema 2 新增章节和制作单表、目录查询索引。迁移不改写旧正文和历史媒体，升级前保留可恢复备份。

## 查询和 Agent

- Studio `GET /api/state?view=studio` 返回章节、场景、镜头、资料和会话摘要；`GET /api/object` 按项目与对象读取完整正文。
- `GET /api/search` 与 `dreamer_search` 共用查询：按项目隔离，章节号 / 标题 / 正文、卷、状态、章节范围、制作单范围及 offset / limit。每页最多 50 条；制作单镜头按单内顺序返回。
- `dreamer_read` 读取固定版本；章节正文最多每次 12,000 个 UTF-16 字符，附带原文总长及下一段位置。字符位置与浏览器选区一致。
- `change.text` 校验固定原文选区，再由服务端拼回完整正文，形成普通 ChangeSet。Agent 修改章节正文必须走此入口，不能把分页结果当全文替换；审批仍受目标范围、版本和依赖检查约束。
- 会话可按文字查找公开记录。工作台总快照不携带全工程的会话正文；当前打开会话按需读取，页面分批显示。当前单个会话仍一次读取其完整公开历史，并非服务器端历史分页。

## 验收与后续容量边界

`tests/09-longform.test.ts` 使用 1,200 章、1,200 场景和 6,000 镜头。覆盖深处章节正文定位、分页、卷过滤、项目隔离、两章十镜头的 120 秒编排、单内排序隔离、版本冲突、固定成片、AI 分段读取与局部修改。

`npm run test:longform` 在隔离工程的 Chrome 中完成目录、书签、选区交给 Agent、人工保存、制作单、分镜过滤和 120 秒占位预演；使用确定性 Agent fixture，不冒充真实模型生成。报告和截图在 `test-results/longform/`。

当前检索使用 SQLite 子串查询；章节号 / 项目 / 关联查询有索引，正文尚未使用 FTS 或向量索引。摘要快照仍包含全工程目录，千章规模由本轮测量覆盖；超出该规模时可在保持接口的前提下进一步增量化目录和分页会话。故事本身的长期一致性、篇章质量与最终视频质量仍需内容审阅。
